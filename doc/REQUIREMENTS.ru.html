Требования. Программа поиска.

0.0.7
Аннотация
Документ описывает требования к приложению words-searcher — программе просмотра дерева каталогов с последующим поиском. Версия 1 — заготовка: приложение отображает дерево директории, заданной в настройках; эта директория является областью, в которой в последующих версиях будет выполняться поиск. Цель версии 1 — отработать инфраструктуру (сборка в GitLab CI, аутентификация через Keycloak) и базовый графический интерфейс. Документ содержит термины, окружение, требования по частям, пользовательский интерфейс, нефункциональные требования, критерии приёмки и неподтверждённые предложения.

1. Термины и определения

Программа поиска
Приложение words-searcher. В версии 1 поиск не выполняется: программа отображает дерево каталогов; область будущего поиска совпадает с корневой директорией.
Корневая директория
Директория, указанная в настройках; её содержимое образует корень дерева и является областью, в которой в последующих версиях будет выполняться поиск.
Узел
Элемент дерева: каталог или файл.
Колонки
Иконка, Дата, Имя, Размер (см. часть «Отображение дерева»).
Состояние сортировки
Одно из трёх для каждой колонки: «никакое», «по возрастанию», «по убыванию».
Тема оформления
Светлая или тёмная цветовая схема интерфейса приложения, задаваемая явно через палитру и сохраняемая в настройках.
Масштаб шрифта
Отклонение размера шрифта интерфейса от исходного (базового) размера, выраженное в пунктах; сохраняется в настройках.
Операционная среда
Именованный шелл (bash), в котором выполняется команда. В документе сокращение «ОС» означает именно операционную среду, а не операционную систему.
Дистрибутив
Дистрибутив GNU/Linux, на котором настроена операционная среда и который она использует. Например, ОС Toliman настроена на дистрибутиве Debian 13 trixie.

2. Окружение

ОС Toliman
Операционная среда рабочей машины, настроенная на дистрибутиве Debian 13 trixie. В ней ведётся разработка и локальная сборка программы поиска. Соответствует «рабочей среде» (Ctrl+F1).
ОС lacaille9352
Операционная среда, доступная как Ctrl+F2. Хост для докера: в ней запущены контейнеры gitlab, ci-runner, keycloak-v26.8.0. Используется инфраструктурой сборки и аутентификации.
Целевые платформы распространения
Debian и Gentoo — платформы, для которых готовятся артефакты программы поиска.

3. Назначение и область применения


Программа поиска — графический просмотрщик содержимого файловой директории в виде дерева. Корневая директория задаётся в настройках приложения. Настройки редактируются диалогом, вызываемым из строки меню.

Область применения версии 1: локальный просмотр дерева каталогов на рабочей машине без редактирования содержимого (режим только чтения). Поиск в версии 1 не выполняется; имя приложения отражает будущую функцию.

Стек: C++/Qt6, система сборки Autotools. Подробности сборки — в документе «Сборка. Qt6, autotools, debian, gentoo».

4. Отображение дерева

Т_1. Программа должна отображать дерево каталогов от корневой директории, заданной в настройках.
Т_1.1. Дерево должно отображать каталоги и файлы; вложенность должна раскрываться по запросу (ленивая загрузка).
Т_1.2. Содержимое узла должно загружаться при его раскрытии, а не целиком при старте.
Т_1.3. Скрытые файлы и каталоги (имя начинается с точки) по умолчанию не должны показываться; видимость должна переключаться в настройках и пунктом меню «Вид → Показать скрытые».
Т_2. Дерево должно иметь четыре колонки в следующем порядке: Иконка, Дата, Имя, Размер.
Т_2.1. Колонка «Иконка» должна содержать только иконку типа (каталог/файл), без текста; заголовок пустой или скрыт.
Т_2.2. Колонка «Дата» должна содержать дату изменения узла в формате YYYY-MM-DD, только текст; формат одинаков для файлов и каталогов; для каталога используется mtime самого каталога.
Т_2.3. Колонка «Имя» должна содержать имя узла, без иконки.
Т_2.4. Колонка «Размер» должна содержать размер файла в человекочитаемом виде (например, 340 B, 1.2 KiB); для каталогов — пусто; колонка последняя.
Т_4. Раскрытие и сворачивание узлов должно выполняться стандартными средствами дерева (клик по индикатору раскрытия, клавиши).
Т_5. Изменения на диске в раскрытых узлах должны отслеживаться и отражаться в дереве автоматически (наблюдение за файловой системой).
Т_5.1. Пункт меню «Вид → Обновить» (горячая клавиша F5) должен выполнять принудительное обновление дерева.
Т_8. Запуск и первичное отображение корня должны выполняться без полного обхода дерева (ленивая загрузка).
Т_8.1. Работа с каталогами большого объёма (десятки тысяч узлов в раскрытом узле) не должна приводить к зависанию интерфейса.

5. Сортировка

Т_3. Сортировка должна выполняться по клику на заголовок колонки. Расширенные правила (три состояния, ключи, каталоги в конце по размеру) — в разделе 14 «Неподтверждённые предложения (инициативы)».

6. Действия с узлами

Т_4.2. Контекстное меню (по правой кнопке) на узле должно содержать:
- для директории: «Копировать каталог», затем разделитель, затем «Открыть директорию в Dolphin», «Открыть директорию в Nautilus»;
- для файла: пункты для каждого редактора из настроек (если список не пуст), затем разделитель, затем «Копировать каталог», «Копировать путь с именем файла», затем разделитель, затем «Открыть файл в Firefox».
Пункт «Копировать путь с именем файла» для директории не показывается. Дублирующихся разделителей быть не должно.
Т_4.3. Редактирование содержимого (переименование, удаление, создание, перетаскивание) в версии 1 не выполняется.
Т_4.4. Список редакторов для открытия файлов должен задаваться пользователем в настройках (многострочное поле, по одному редактору на строку). В контекстном меню файла должны отображаться пункты для каждого редактора из списка (в порядке, заданном пользователем), затем разделитель, затем «Копировать каталог», «Копировать путь с именем файла», затем разделитель, затем «Открыть файл в Firefox». Имена конкретных редакторов в коде не зашиваются.

7. Настройки

Т_6. Настройки приложения должны включать: путь к корневой директории; путь к исполняемому файлу редактора (по умолчанию gedit); показывать скрытые файлы и каталоги (да/нет; по умолчанию — нет); геометрию главного окна (размер и позиция; сохраняется и восстанавливается); выбранную тему оформления; масштаб шрифта.
Т_6.1. Диалог настроек должен вызываться из строки меню: «Справка → Настройки…».
Т_6.2. Диалог настроек должен быть модальным окном и содержать: поле ввода пути к корневой директории и кнопку «Обзор…»; поле ввода пути к редактору и кнопку «Обзор…»; флажок «Показывать скрытые»; кнопки «OK», «Cancel», «Apply».
Т_6.3. «OK» должен применять изменения и закрывать диалог; «Cancel» — закрывать без применения; «Apply» — применять без закрытия.
Т_6.4. После применения нового пути дерево должно перестраиваться от новой корневой директории.
Т_6.5. Если указанный путь не существует или недоступен для чтения, должно выводиться сообщение об ошибке; настройка не применяется.
Т_6.6. Настройки должны храниться средствами штатного механизма настроек Qt (INI-файл или нативная схема платформы).
Т_6.7. Настройки должны сохраняться при выходе и при нажатии «Apply»/«OK» в диалоге.
Т_6.8. Выбранная тема оформления должна сохраняться при переключении и восстанавливаться при следующем запуске приложения.
Т_6.9. Масштаб шрифта должен сохраняться при изменении и восстанавливаться при следующем запуске приложения.

8. Удобство использования

Т_7. Главное окно должно содержать строку меню: «Поиск» («Выход»); «Вид» («Обновить» (F5), «Показать скрытые» (флажок), «Увеличить шрифт», «Уменьшить шрифт»); «Справка» («Настройки…», разделитель, «Русский», «Английский», разделитель, «Светлая тема», «Тёмная тема», разделитель, «О программе»).
Т_7.1. Центральная область главного окна должна быть деревом с четырьмя колонками (см. часть «Отображение дерева»).
Т_7.2. Строка состояния должна отображать текущий корневой путь и, при необходимости, сообщения об ошибках.
Т_7.3. Заголовки колонок: пустой (Иконка), «Дата», «Имя», «Размер».
Т_7.4. Пункты меню «Вид → Увеличить шрифт» и «Вид → Уменьшить шрифт» должны изменять размер шрифта интерфейса приложения (в том числе шрифта дерева, строки меню и строки состояния). Увеличение — по нажатию Ctrl +, уменьшение — по нажатию Ctrl -. Масштаб шрифта должен сохраняться между запусками приложения.
Т_7.5. Для масштабирования шрифта должны быть предусмотрены клавиатурные сокращения: Ctrl + (увеличение) и Ctrl - (уменьшение); они должны работать в контексте всего приложения, независимо от того, какой виджет имеет фокус, и не должны перекрываться другими акселераторами.
Т_7.6. Пункты меню «Справка → Светлая тема» и «Справка → Тёмная тема» должны переключать тему оформления приложения. Пункты не должны иметь галочек.
Т_7.7. Пункт меню «Справка → О программе» должен быть последним пунктом меню «Справка»; перед ним должен быть разделитель.

9. Надёжность

Т_9. Недоступный путь, отсутствие прав на чтение каталога, удаление корневой директории во время работы должны обрабатываться без аварийного завершения; пользователю должно выводиться сообщение.
Т_9.1. Ошибки чтения отдельных узлов не должны прерывать работу приложения.

10. Кроссплатформенность и технологический стек

Т_10. Целевая платформа версии 1 — Linux.
Т_10.1. Код не должен содержать платформенно-зависимых решений без необходимости; использование штатных средств Qt предпочтительно.
Т_11. Язык: C++; GUI: Qt6 (модули Widgets, Gui, Core).
Т_11.1. Модель данных: штатная модель файловой системы Qt с ленивой загрузкой; поверх неё — прокси-модель для раскладки колонок (иконка, дата, имя, размер), форматирования даты YYYY-MM-DD и размера, а также для трёхсостоятельной сортировки.
Т_11.2. Форматирование ячеек — делегат отрисовки для колонок «Дата» и «Размер».
Т_11.3. Отслеживание изменений на диске — штатный механизм наблюдения за файловой системой Qt.
Т_11.4. Настройки — штатный механизм настроек Qt.
Т_11.5. Открытие файлов и каталогов во внешних программах — штатные средства Qt.
Т_11.6. Система сборки — Autotools (см. документ «Сборка. Qt6, autotools, debian, gentoo»).
Т_11.7. Тема оформления должна задаваться явно через QPalette (светлая — стандартная палитра стиля, тёмная — заданный набор цветов), а не полагаться на QStyleHints::setColorScheme(), так как на Linux соответствующие вызовы могут игнорироваться платформенной темой.
Т_11.8. Масштаб шрифта должен вычисляться от запомненного исходного (базового) размера шрифта, а не от текущего, чтобы избежать двойного учёта отклонения.
Т_12. Интерфейс версии 1 поддерживает русский и английский языки (см. Т_14); исходный язык сообщений — русский.
Т_12.1. Рабочее имя приложения — words-searcher.
Т_13. Интеграция GitLab с Keycloak должна быть настроена до запуска первых pipeline (см. документ «Сборка. Qt6, autotools, debian, gentoo»).

10.5. Интернационализация


Т_14. Исходный язык сообщений программы — русский.
Т_14.1. Должна поддерживаться локализация интерфейса на английский язык; локализация — на английский.
Т_14.2. Все пользовательские строки (меню, диалоги, сообщения, заголовки колонок, заголовок окна) должны быть обёрнуты в tr().
Т_14.3. Файлы перевода (.ts, .qm) должны размещаться в translations/ и встраиваться в бинарник через resources.qrc.
Т_14.4. В configure.ac должны быть предусмотрены проверки и пути к lrelease и lupdate (в Debian — /usr/lib/qt6/bin/).
Т_14.5. Переключение языка должно выполняться в рантайме, через пункты меню «Русский» / «Английский» в «Справке».
Т_14.6. Выбранный язык должен сохраняться в настройках (QSettings) и восстанавливаться при следующем запуске.
Т_14.7. При смене языка должны обновляться: меню, заголовок окна, заголовки колонок, текст в «О программе», а также стандартные кнопки диалога настроек (OK/Cancel/Apply) — для этого должен загружаться системный перевод qtbase_ru.qm (для русского) или qtbase_en.qm (для английского) из проекта Qt Translations (qt/qttranslations, https://code.qt.io/cgit/qt/qttranslations.git).

14. Неподтверждённые предложения (инициативы)

  • Поиск по имени прямо в дереве (строка поиска над деревом) — для версии 2; имя приложения отражает будущую функцию.
  • Поиск по содержимому файлов (с ограничением по размеру файла и типу) — для последующих версий.
  • Расширенная сортировка (Т_3.1–Т_3.5): трёхсостоятельная сортировка по клику (нет / ▲ / ▼) со стандартным индикатором; для «Иконки» — первичный ключ тип (каталог/файл), вторичный имя; для «Даты» — mtime; для «Размера» — байты, каталоги в конце. В версии 1 используется встроенная сортировка Qt без этих правил.
  • Колонка «Тип»/MIME или расширение — полезнее пустой колонки-иконки при сортировке.
  • Сохранение состояния: раскрытые узлы, позиция прокрутки, текущая сортировка — между сеансами.
  • Хлебные крошки / адресная строка с текущим путём и возможностью перейти вверх.
  • Несколько корневых директорий (закладки).
  • Индикация ошибок доступа прямо в узле (например, серый восклицательный знак), а не только в статусной строке.
  • Асинхронная загрузка содержимого узла (поток/воркер), чтобы большие каталоги не подвешивали интерфейс.
  • Защита от циклов симлинков и ограничение глубины.
  • Горячие клавиши: F5 (обновить), Ctrl+F (поиск), Ctrl+H (скрытые), F2/Enter (открыть).
  • Поведение при невалидном корне: ошибка без применения vs пустое дерево + сообщение в статусной строке. В документе принято: ошибка без применения (Т_6.5); альтернатива — в инициативах.
  • Перенос настроек между машинами (экспорт/импорт).
  • Локализация интерфейса (английский язык) — после версии 1.
  • Smoke-тест в CI без дисплея (QT_QPA_PLATFORM=offscreen) — если будет принято как требование, критерий 11 станет обязательным.
